# Annex — dev-workflow-supervisor

Dated rulings, incident narratives and post-mortems behind the rules in `SKILL.md`. The rules live in the body; this annex preserves why they exist, with dates and evidence. Read at reflection time, not at run start.

- **A-S1 — Settle the previous run first (Loop step 0).** Origin: repeated runs hit the time budget with live descendants still working; the work had landed server-side, but the receipts had not been booked, so later runs re-diagnosed finished work and risked duplicate dispatch. Hence: receipts are reconciled from code-host API state and posted to the Work Log before any new dispatch.
- **A-S2 — Merged-PR sweep (Loop step 9).** Origin: record-less merges — including a credential-path change and a production auto-deploy change — surfaced only in a manual audit. A PR merged with no linked issue is invisible to every other step of the loop.
- **A-S3 — Decide it yourself (emulator gate).** Origin: a no-KVM emulator gate sat parked as an "owner decision" ("accept the limitation vs run the fix cycle"). The owner's ruling: the fix was simple, obvious, and the agent's to run. Hence: a limitation with a known technical fix is a fixable defect, never an approval gate; emulator/CI environment fixes (KVM flags, software rendering, timeout raises, runner configuration), test-lane configuration, retry strategy and tooling workarounds are never escalated as a choice.
- **A-S4 — Release authority (2026-11-06).** The project owner stated it explicitly: "It is not my call. You are the product owner." Hence: the release call belongs to the product owner running this protocol; "waiting for the project owner's release call" is a protocol violation, not a state.
- **A-S5 — "Action-time approval" is not a board gate (Den, 2026-11-07).** Ruling: board blockers never wait on the owner's attention; their resolutions are the Supervisor's to execute with evidence. Only runtime safeguard prompts (system-level approval cards) and the three reserved classes (money, the owner's time/presence, credentials only the owner holds) bound the Supervisor's decision rights.
- **A-S6 — Kill-and-restart, free slot, consistency (Den, 2026-11-07).** Three rulings from the same review: (1) a subagent with no runtime activity and no new server-side artifact since the previous sweep is stalled — steering it and waiting another cycle is a failed sweep; kill and replace in the same sweep, briefed at the current stage. (2) A free slot with a workable row left unstaffed is a failed sweep — dispatch in the same sweep; "gated/parked/waiting" is re-proven against current evidence every sweep, never inherited. (3) A task In Progress with no live related subagent is an inconsistent state, not a status.
- **A-S7 — Escalation loophole, closed.** A verified infrastructure-down state escalates however it was learned. Classifying it as "not a blocked dependency" to justify silence was tried and is a closed loophole: silence in the face of a systemic blocker is a protocol violation.
